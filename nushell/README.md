# nushell

A [Please](https://please.build) plugin for running [Nushell](https://www.nushell.sh/) scripts as binaries (`nu_binary`), tests (`nu_test`) and build actions (`nu_genrule`), and sharing Nushell modules between them (`nu_library`).

By default it downloads Nushell itself from [GitHub Releases](https://github.com/nushell/nushell/releases), so it doesn't need to be installed.

## Usage

See the [root README](../README.md#using-a-plugin) for loading it with `plugin_repo` - in `.plzconfig`:

```ini
[Please]
PluginRepo = https://github.com/{owner}/{plugin}/archive/{revision}.zip
PluginRepo = https://github.com/VJftw/please-rules/releases/download/{plugin}-v{revision}/{plugin}-v{revision}.tar

[Plugin "nushell"]
Target = //third_party/plugins:nushell
```

and in `third_party/plugins/BUILD`:

```python
plugin_repo(
    name = "nushell",
    owner = "VJftw",
    revision = "<version>",
    hashes = ["<sha256 from registry/plugins/nushell/<version>/source.json>"],
)
```

Then, in `BUILD` files next to your `.nu` files:

```python
subinclude("///nushell//build_defs:nushell")

# lib/BUILD
nu_library(
    name = "greeting",
    srcs = ["greeting.nu"],
    visibility = ["PUBLIC"],
)

# app/BUILD
nu_binary(
    name = "hello",
    src = "hello.nu",  # `use lib/greeting.nu`
    deps = ["//lib:greeting"],
)

nu_test(
    name = "hello_test",
    src = "hello_test.nu",  # `use std/assert`, `use ../lib/greeting.nu`
    args = ["VJ"],
    data = ["name.txt"],
    deps = ["//lib:greeting"],
)
```

```console
$ plz run //app:hello -- VJ
$ plz test //app:hello_test
```

## Rules

- **`nu_binary`**: a Nushell script (`src`), runnable with `plz run //path:name -- <args...>`. Any `def main [...]` it defines is called with those arguments, the same as `nu <src> <args...>` - declare it with `--wrapped` to receive arbitrary flags as-is. `deps` lists the `nu_library` rules it `use`s, and `data` any other files it needs at runtime.
- **`nu_test`**: the same, run as a test - passes iff the script exits 0, so an uncaught error (e.g. a failed assertion from Nushell's own `std/assert` module) fails it. `args` are passed to its `def main`; `timeout`, `flaky`, `size` and `sandbox` work as for any other Please test.
- **`nu_genrule`**: runs a Nushell script (`src`) at build time - `nu --no-config-file <src> <args...>` - to produce `outs`. It runs in the build's temporary directory, where `srcs` and `deps`' outputs are at their paths relative to the repository root (also on the include path, so `src` can `use` a `nu_library` from `deps`). `args` go through the shell first, so Please's build variables work in them, e.g. `$OUTS` or `$(location :foo)`.
- **`nu_library`**: a reusable set of Nushell modules (`srcs`), that can itself `use` other `nu_library` rules via `deps`. A library's `deps` come along with it, so a rule only needs to list the libraries it `use`s directly - see `examples/lib/BUILD`'s `greeting`/`shout`.
- **`nushell_tool`**: downloads Nushell for the host platform (Linux and macOS, amd64 and arm64). Used for the default `Tool`, and can be used directly to provide your own, e.g. a different `version` with your own `hashes`, or a `url_template` (with `{version}` and `{asset}` placeholders) for a mirror.

Scripts run with `nu --no-config-file`, so they behave the same regardless of the invoking user's own Nushell config.

## Using modules

A module from a `nu_library` in `deps` can be `use`d either:

- relative to the script using it, e.g. `use ../lib/greeting.nu`; or
- relative to the root of the repository, e.g. `use lib/greeting.nu` - this works the same from any script at any depth, and for a module generated by another rule (e.g. a `genrule` in `srcs`) as well as a source file.

Nushell's own standard library (`use std/assert`, ...) is built into `nu` and needs no `deps`.

## Runtime files

A `nu_binary`/`nu_test` can find its `data` (or any other runtime file) wherever Please has put it with the `runfiles.nu` module, which every launcher puts on the include path:

```nu
use runfiles.nu
open (runfiles rlocation app/name.txt)
```

Paths are relative to the repository root, for source files and other rules' outputs alike. They're found where Please stages them for a test (or `plz run --in_tmp_dir`), or otherwise - for a plain `plz run` - in the repository and its `plz-out` directories.

## How it works

`nu_binary`/`nu_test` build a small `/bin/sh` launcher that runs `nu --no-config-file --include-path <dirs> <src> <args...>`, propagating its exit code. `nu`, `src` and every (transitive) library are runtime dependencies of it, which Please stages next to a test (including a sandboxed one) and for `plz run --in_tmp_dir` - the launcher uses those when they're there. A plain `plz run` doesn't stage anything, so the launcher instead finds them relative to the repository root, which it works out from its own path (always under `plz-out`). Copying the launcher out of `plz-out` and running it from elsewhere isn't supported.

## Configuration

| Key           | Default                          | Description |
| ------------- | -------------------------------- | ----------- |
| `Tool`        | `//third_party/nushell:nu\|nu`   | The `nu` executable: a build target (with an optional `\|entry_point`), or a command on the host's PATH. |
| `ToolVersion` | `0.116.0`                        | The Nushell version the default `Tool` downloads. |

Every Nushell release's checksums are in the plugin's mirror, `build_defs/versions.build_defs` - see [Checksum mirrors](../README.md#checksum-mirrors) (`cd .github && plz run //scripts/mirrors:nushell`).

If `Tool` is a command on the host, note that Please runs tests with its own `[Build] Path`, so `nu` must be on that path for `nu_test` to find it.

## Testing

[`examples/`](./examples) is a separate Please repository that consumes this plugin the same way an end user would, except it loads it from this local checkout via `subrepo(name = "nushell", path = "..", plugin = True)` (the equivalent of `new_local_repository`, which doesn't support `plugin = True`). Its `nu_test`s (one sandboxed) exercise both kinds of `use`, a transitive `nu_library`, `args`, `data` - including a `nu_genrule`'s output, found with `runfiles.nu` - and the pinned Nushell version:

```console
$ cd examples && plz test //...
$ plz run //app:hello -- VJ
```

## Layout

- `.plzconfig` - the plugin definition and its configuration options.
- `VERSION` - the plugin's current version.
- `build_defs/nushell.build_defs` - `nu_binary`, `nu_test`, `nu_genrule`, `nu_library` and `nushell_tool`.
- `build_defs/versions.build_defs` - the generated checksum mirror.
- `runfiles/runfiles.nu` - the `runfiles.nu` module (see above).
- `third_party/nushell/BUILD` - the default `Tool`: a `nushell_tool` at `ToolVersion`.
- `examples/` - an example repository, used for testing (see above).
